# 会话命名：重命名 + AI 生成名字

> **状态**：设计已定，待实现（`backend-core` 做后端，`web-ui` 做前端）
> **提出人**：用户（2026-10-15）"会话名需要加一个重命名/AI 生成会话名的功能"
> **Lead 裁定**：契约以本文件为准；**两端不许各自解释**

## 1. 现状（Lead 实测）

```
conversations 表**已有** title 字段:
  CREATE TABLE conversations (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    doc_id TEXT, title TEXT DEFAULT '',
    created_at INTEGER NOT NULL
  )

★ 但库里所有会话的 title 都是默认占位符 '新问答':
  {'id': 'cnv_96f547dfb91f', ..., 'title': '新问答'}
  {'id': 'cnv_55b149de21dc', ..., 'title': '新问答'}
  ... （连续 6+ 个一模一样）
⟹ 会话列表**一排相同的"新问答"，用户找不到任何一个会话** —— 这是本需求的根因。

⚠️ 后端**没有**会话改名端点（rbac.ts:298 的 title 是文档的，不是会话的）。
```

## 2. ★★ 核心设计决定：`title_source`（必须加）

**问题**：若 AI 自动命名与用户手动命名**共用一个 title 字段**，那么
**AI 会在用户改完名字之后把它覆盖掉** —— 这是"用户改了、系统又改回去"的经典冲突。

**解决**：新增字段，记录**名字是谁定的**：

```
ALTER TABLE conversations ADD COLUMN title_source TEXT NOT NULL DEFAULT 'default'
  · 'default' —— 系统占位（如 '新问答'）
  · 'ai'      —— AI 生成的
  · 'user'    —— ★ **用户手动设定的**
```

**★ 铁律**：
```
title_source === 'user'  → ★ **AI 永远不许覆盖**（自动命名跳过、手动"重新生成"也要先确认或直接拒绝）
title_source === 'ai'    → 允许 AI 重新生成（自动或手动）
title_source === 'default' → 允许 AI 自动命名
```

**⚠️ 为什么不复用 `title === '新问答'` 做判据**：
```
用户完全可以把会话命名成"新问答" → 之后 AI 会认为"还是默认值"而覆盖它
★ **用内容当状态 = 自述与生效不同源**（我们一路在防的那族）
⟹ **必须有独立字段**
```

**迁移**：新增 **v7** 迁移（`addMissingColumns` 幂等机制 + **新版本号** —— v5 的教训：
改旧块对已迁移库无效）。**已存在的行** → `title_source='default'`（它们的 title 都是 '新问答'）。

## 3. 后端契约

### 3.1 重命名（用户手动）

```
PATCH /api/v1/conversations/:id
Body: { "title": "聚簇索引与二级索引的区别" }
200:  { id, title, title_source: 'user', created_at }
```

**要求**：
```
① ★ **归属校验（IDOR）** —— 必须校验会话属于当前用户。
   复用 `store/chat-session-owner.ts` 的**单一归属判定点**（fail-closed）。
   ★ **不可见 → 404（不泄露存在性）**，与 reparse 端点同一策略。
② 校验: trim 后长度 **1..80**；全空白 → 400（`E_BADREQUEST`）；超长 → 400（**别静默截断**）
③ ★ 设定后 `title_source = 'user'`
④ ★ 非法 id → 404；非本人 → 404（**不许 403 泄露存在性**，与 3.1① 一致）
⑤ ★ **幂等**：重复设置同一 title → 200（不报错）
```

### 3.2 AI 生成名字

```
POST /api/v1/conversations/:id/title/generate
200:  { id, title, title_source: 'ai' }        ← 同步返回（命名很快）
202:  { task_id, events_url }                  ← 若走异步（见下）
409:  { error: { code: 'E_TITLE_USER_SET' } }  ← ★ title_source==='user' 时拒绝
```

**要求**：
```
① ★★ **`title_source==='user'` → 拒绝（409 E_TITLE_USER_SET）**，并在 msg 里说清
   "该会话名由你手动设定，未被 AI 覆盖"
   ★ **不静默跳过** —— 用户点了"生成"却什么都没发生，会被当成 bug
② ★ 输入 = **首条用户提问 + 首条助手回答**（各截断到 ~500 字符）
   · 若**还没有任何消息** → 400（"先聊一句再生成"）—— **不编名字**
③ ★ 输出后处理（模型一定会加引号/解释，必须清洗）：
   · 取**第一行** · 去掉首尾引号（中英文 `"'“”‘’`）· 去掉结尾标点
   · 截断到 **20 个字符**（中文）/ 40 字符（含英文）—— **如实截断，不许留半个词**
   · 若清洗后为空 → **保留原名** + 如实记警告（**不写空名字**）
④ ★ **max_tokens 要小**（如 32）—— 命名不需要长输出，**成本必须极低**
⑤ ★ **失败 → 保留原名**（不阻塞对话、不写占位、不假装成功）
⑥ ★ 并发：命名调用走同一个 `LLM_QUEUE`（并发=1）
   ⟹ ★ **长抽取在跑时，命名会排队** —— 因此：
      · **优先同步返回**（命名很快），若必须异步 → 用 `events_url` 如实显示"生成中"
      · ★ **绝不许阻塞聊天流**（聊天是主路径，命名是附属）
⑦ ★ 命名成功后**若会话已在列表中，前端应更新显示**（见 4.3）
```

### 3.3 列表/详情要带 `title_source`

```
GET /api/v1/conversations → [{ id, title, title_source, created_at, ... }]
GET /api/v1/conversations/:id → 同上
⟹ 前端据此决定: 是否显示"AI 生成"标记、是否允许"重新生成"
```

## 4. 前端契约

### 4.1 重命名
```
· 会话列表项 → 双击或右键菜单「重命名」→ **行内编辑**（input）
· Enter 提交 / Esc 取消 / 失焦提交（**三选一要明确，建议 Enter + Esc，失焦取消**）
· ★ 提交后**乐观更新**（立即显示新名字），失败则**回滚 + 如实提示**
· ★ 空白名 → 本地拦截（不发请求）
· ★ 长度上限在 UI 上可见（如 `0/80` 计数），但**服务端才是权威**（别只靠前端）
```

### 4.2 AI 生成
```
· 会话列表项菜单 / 对话页头部 → 「AI 生成名字」（无名字时）/「重新生成」（已有 AI 名字时）
· ★ `title_source==='user'` 时 → **按钮禁用或点击后如实提示"已由你手动命名"**
· ★ 生成中显示「生成中…」（**别让用户以为点了没反应**）
· ★ 失败 → 保留原名 + 如实提示（**不静默**）
· ★ 自动命名：**首次"用户提问 + 助手回答"完成后**自动触发一次
  · 只在 `title_source==='default'` 时触发（**只触发一次**，之后不重复）
  · ★ **失败不重试到天荒地老**（如实标注即可）
```

### 4.3 显示
```
· 列表项: 名字 + （可选）`AI` 小标记
· ★ **没有名字时不要显示 '新问答' 一排** —— 建议显示**首条用户提问的前 20 字**（本地派生，零成本）
  · 这只是**显示层兜底**，不写库（库里的 title 仍为默认值）
  · ★ 这样用户**立刻**能区分会话，不必等 AI 命名
```

## 5. ★★ 与"学生工作区目录"的关系（**必须明确**）

用户早前要求：学生私有存储目录用 **`会话名+时间`** 命名（如 `聚类索引问答2610151748`）。
**会话名会成为目录名** ⟹ 必须处理：

```
① ★ **目录名 = 创建时的 title 快照**，**不是** title 的活引用
   ⟹ **改名会话不自动改目录名**（改目录名会影响已引用的文件路径）
   若要支持"改名同时改目录" → 作为**独立功能**另议，**本需求不做**
② ★ **目录名必须消毒**（若将来启用）:
   · 去掉 `\ / : * ? " < > |` 与控制字符
   · 去掉首尾空格与结尾的点（Windows 不允许结尾 `.` 或空格）
   · ★ 禁止 Windows 保留名: `CON PRN AUX NUL COM1-9 LPT1-9`
   · 禁止 `..` 与绝对路径片段
   · ★ **长度上限**（含时间戳后仍要短）
   · ★ **消毒后为空 → 用默认名**（如 `会话`）—— **不许生成空目录名**
③ ★★ **路径安全**：目录名**永远不能**被拼成可逃出学生根目录的路径 ——
   拼接后必须 `realpath` 校验仍在根目录内（**不是字符串 startsWith** —— 我们定过的判据）
④ ★ **惰性创建**：工作区目录**在首次文件操作时**才创建，用**当时的** title
   ⟹ AI 命名（发生得早）通常已生效，目录名自然就是 AI 名
```

## 8. 参考：为什么这些约束是这样

| 约束 | 出处 |
|---|---|
| `title_source` 独立字段 | 坑 21：**自述与生效不同源**；用内容当状态不可靠 |
| 归属校验 fail-closed + 404 | IDOR 修复（方案 A）：`store/chat-session-owner.ts` 单一判定点 |
| 迁移要用新版本号 | v5 教训：**改旧块对已迁移库无效** |
| 失败保留原名 | 铁律：**如果一个 bug 的表现是"看起来成功"，它比崩溃危险得多** |
| 目录名消毒 + realpath | 学生工作区设计要求：**路径限制用 realpath，不是字符串前缀** |
| 命名成本极低 | 并发=1：**命名必须小、必须快、绝不阻塞聊天** |
